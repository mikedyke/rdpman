# rdpman

Portable manager for Windows Remote Desktop sessions. One native Win32 executable written in C++
with the static CRT: no .NET, no installer, no third-party libraries. Connections are launched
through the built-in `mstsc.exe`.

## Hard requirements

- Must stay a single self-contained exe. Do not add a dependency on .NET, a redistributable
  runtime, or any DLL that does not ship with Windows 10+.
- Must stay portable: user data lives next to the exe (`sessions\*.rdp`, `rdpman.ini`), with a
  fallback to `%APPDATA%\rdpman` only when the exe folder is not writable.
- Existing `.rdp` files must round-trip. Lines the program does not know are kept verbatim, and
  settings a file does not contain must not be written just because the editor was opened.

## Build

```
build.cmd
```

Locates Visual Studio through `vswhere`, calls `vcvars64.bat`, and compiles `rdpman.cpp` with
`/MT /O1`, embedding `app.manifest` (common controls v6, per-monitor-v2 DPI awareness). There is
no project file, no resource script and no test suite. CI (`.github/workflows/build.yml`) runs the
same script on `windows-latest`; pushing a `v*` tag publishes a release with the exe.

The exe is locked while it runs: stop any running `rdpman.exe` before rebuilding.

## Layout

Everything is in `rdpman.cpp`, in this order:

| Section | Contents |
| --- | --- |
| helpers | `Fmt`, `Trim`, `Split`, `ParseIds`/`JoinIds`, `ws` = `std::wstring` |
| property table | `g_defs[]`: every known RDP setting with type, default, category, editor page, control kind, label, choices, description |
| file model | `RdpFile` (ordered `Line` list), `ParseLine`, `Load` (UTF-16/UTF-8/ANSI), `Save` (UTF-16 LE with BOM) |
| password | `EncryptPwd`/`DecryptPwd`, DPAPI blob for `password 51:b:` |
| monitors | `EnumMons`, `Contiguous`, snapshot (`ParseSnap`/`MakeSnap`), `MonitorIssue`, `IdentifyMonitors` |
| UI plumbing | `Ctl`, `S()` DPI scaling, `CreateModal`/`RunModal`/`EndModal`, `Prompt` |
| editor | `Editor` state (global `E`), monitor picker control, `Push`/`Pull`, "All settings" list, `EditSession` |
| main window | session list, `Connect`, import/export, `MainProc`, `wWinMain` |

## Things that are easy to get wrong

- **Monitor IDs.** The IDs `mstsc` uses in `selectedmonitors` (and shows with `mstsc /l`) are the
  display device index from `EnumDisplayDevices` (`\\.\DISPLAY3` is usually 2), not the
  `EnumDisplayMonitors` order. IDs can have gaps. `MonEnumProc` does this mapping; keep it.
- **Adding a setting** means adding one row to `g_defs[]`. A row with a page and a control kind
  gets a control generated by `LayoutAuto` and is synced by `Push`/`Pull` automatically; a row
  with `P_NONE` appears only on the "All settings" tab.
- **`Push`/`Pull`.** `Push` copies the model into the controls, `Pull` copies back. `Pull` skips a
  setting that is absent from the file and still at its table default, so editing an imported
  file does not add lines. `Pull(true)` writes everything and is used only for new sessions.
  The tab-change handler pulls when leaving a curated tab and pushes when leaving "All settings".
- **`rdpman ...` keys** (`rdpman group`, `rdpman notes`, `rdpman args`, `rdpman monitors`) are the
  program's own metadata. `Save(path, true)` strips them; that variant is used for exports and
  for the temporary copy in `%TEMP%\rdpman` that is handed to `mstsc`.
- **Monitor snapshot.** `rdpman monitors` stores `id@x,y,w,h;...` for the monitors a session was
  set up for. `MonitorIssue` compares it with the attached monitors and returns one line per
  problem, or an empty string. It is used by the list (`DisplaySummary`), `Connect` and the editor.
- **Coordinates** are written in 96-dpi units and scaled with `S()`. The process is
  per-monitor-v2 DPI aware, which is also what makes monitor rectangles come back in physical
  pixels; do not lower the awareness level.
- **Windows macros.** `IDC_SIZE` and similar names are already defined by `winuser.h`. Check
  before naming a control id `IDC_*`.
- **Dialogs** are plain windows driven by `RunModal` with `IsDialogMessage`, not dialog resources.
  Tab pages are siblings of the tab control (class `RdpManPage`) and forward `WM_COMMAND` and
  `WM_NOTIFY` to the editor window.

## Checking a change

There are no automated tests. Build, start the exe, and look at it. For scripted checks, session
files can be written straight into `sessions\`, `rdpman.exe "session name"` connects from the
command line, and the file passed to `mstsc` can be inspected in `%TEMP%\rdpman`. Use a host such
as `rdpman-test.invalid` and close the `mstsc` process afterwards. Screenshots taken with
`PrintWindow` sometimes omit the tab strip of the editor; a real screen capture shows it.

Remove test sessions and `rdpman.ini` afterwards; both are ignored by git, as is `rdpman.exe`.
